## 修复与证明

`array_constructor_regions` 现在允许纯字符串键记录根，以及记录字段递归包含数组或
记录表。每个子表仍需匹配原始 NEWTABLE 分配、临时槽、字段顺序和批次；它必须由
紧随的父 SETTABLE 消费。大 RK 键占一槽，子表从下一槽开始。试解析失败会回滚，
避免把父数组的下一条兄弟记录吞为字段；不能单凭圆整后的 hash hint 判定结束。

空表没有 SETLIST，外层消费负责确认边界。50／100 项的完整子数组可以由紧随的父
SETTABLE 确认结束。子区间首次跨越 RK 阈值的操作数同步进入父记录的常量池证明。
字段数已不可能容纳下个子表时跳过递归试探，减少平铺记录兄弟的重复解析。

新增 GC 回归发现：大常量池中的 `last = Catalog.last + 1` 会把数字装入寄存器，
原记录表达式栈不接受这种数字来源，导致整个区间退回分步生成。分步形状使更早的
二元表达式右值在后续 `__index` 内仍被弱表观察到，而原始执行此时已经回收它。
基线输出虽然通过 Strict 和重编译，`env:Nested418Probe` 处是 `live`，原始为 `dead`。

现有记录栈因此补齐有限数值的寄存器右操作数：运行时左值位于 Rn，紧随 LOADK 到
Rn+1，再由同序 BinaryOp 写回 Rn。低索引数字须有此前池满证据，高索引数字自身提供
证据；数值保留 LOADK 来源，不能冒充查表基值或动态键。至少一边是运行时表达式，
不会触发 Lua 的双字面量常量折叠。反向操作数、错误写回槽和非有限数字不借此放行；
inf／NaN 的源码拼写会引入额外运算，不能声称保留原指令和 GC 槽覆盖。

实现仍复用已有完整区间事务，没有放宽入口帧、定义／使用、捕获身份或开放包证明。
捕获路径仍不跨越前序全局构造／函数安装；同一表混合数组和记录字段、数值／动态
记录键、嵌套开放尾项、数组直接 LOADBOOL／LOADNIL 不在本轮区间证明内。

还有一个已确认的保守 RK 缺口：父字段键恰为 K255、子记录只复用旧键和旧数值时，
父键先入池的证据直到子表之后的 SETTABLE 才出现在指令流中。子解析器仍可能拒绝
该 LOADK；后续需显式传递已证明的父键上下文，不能使用最终常量池大小代替。
