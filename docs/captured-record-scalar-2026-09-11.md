# 捕获记录之后的标量声明与开放数组（430）

本轮继续检查八份春节舞狮脚本。输入只作解析、Strict 反编译和重新编译；没有执行
游戏脚本。运行语义验证使用本轮原创的
`tests/regress-case/regress_430_captured_record_scalar_open.lua`。

## 实际阻断

八份根 proto 都有 133 条规范 LIR，`@124` 的闭包按同一顺序捕获
`r3, r1, r2, r0`。以“喜”（SHA-256
`044d7dd7411be3663f8c2c5cb75c267a49ba32b805cbaee7e9e0a9cb0ec8e289`）为例：

- `@12..54` 是全局数组，之后四次函数安装。
- `@63..78` 是捕获记录，字段包含调用和两层嵌套数组。
- `@79` 为下一捕获局部 `r1 = 1`。
- `@80..113` 为捕获数组；末次调用使用开放结果。
- `@114..123` 为另一捕获数组，随后安装四个全局函数并返回。

首个失败发生在 `@79`。记录解析器没有“下一条捕获标量声明”这个完成边界，继续把
LOADK 当作当前记录的字段 producer，最终拒绝；它并非首先被开放尾项阻断。

## 完成边界的证明

只有顶层记录已按原顺序完整形成、没有待消费字段值，且精确字段计数重新编码后的
NEWTABLE 分配 hint 与原值相同，才检查下一条 LOADK。该 LOADK 必须写入紧邻的
下一个局部槽，其**当前 SSA 定义**必须被后续闭包捕获，下一条也不能直接向当前
记录写字段。

常量池另有两条独立路径：

1. 常量在当前构造区间内已经使用过，保留既有池项顺序。
2. 新常量为有限数值，**整个 proto 的最终常量数不超过 255**，后面立即是再下一槽
   的 NEWTABLE，且这个 NEWTABLE 的当前 SSA 定义也被捕获。

第二条使用最终常量数作为上界，证明本 proto 编译期间**从未跨过 RK 容量**。
它没有拿最终大常量池倒推某个早期时点“已经满池”。在这个上界内，规范记录的
数值键和值应直接使用 RK；单独的数值 LOADK 连同捕获身份和下一个捕获表声明，才
提供这个新局部边界。高池且未见过的新数值继续拒绝。

原记录声明及其捕获身份保持不变。下一标量、开放数组、后续数组和闭包安装仍各自
经过已有帧证明；开放数组只有整个后缀闭合时才提交。没有删除原入口、SSA 使用
范围、分配 hint 或开放尾项后缀检查。

## 语义验证

430 的七项定向测试全部通过：13 份正例源码 × 两种调试信息 × 三种命名，共
78 组 Strict、运行结果、整个 builder LIR 与常量池逐项比较；另有六组拒绝检查。

原创样例依次使用开放尾项宽度 0、1、3、60、120，并混入 nil 空洞。后续闭包安装
时，测试回调清空数组、清掉记录中的对象字段，再触发 GC。原始 Lua 5.1 的结果为：

| 开放结果宽度 | 清空前数组长度 | 清空后仍存活的弱引用对象 |
| --- | ---: | ---: |
| 0 | 7 | 0 |
| 1 | 8 | 0 |
| 3 | 10 | 1 |
| 60 | 66 | 1 |
| 120 | 10 | 1 |

后续固定数组只覆盖到 `r11`；开放结果留在 `r12` 的对象应继续存活。重编译产物
同时保留这种 scratch 寿命和含孔数组的长度行为。

拒绝例分别覆盖未捕获的标量、高池未见新数值，以及把标量 LOADK 改成字段存储后
使闭包实际捕获旧字段临时值的字节码。额外正例跨越记录 hash hint 的圆整边界，并
覆盖六份其余舞狮使用的新数值局部。

命令：

```sh
cargo test --locked --offline --test regressions_398_399_record_regions regressions_430
```
