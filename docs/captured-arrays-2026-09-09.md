## 已建立的恢复能力

1. **记录字段的表达式栈。** GETTABLE 可以依次产生左右子表达式；二元运算只允许
   按原顺序消费栈顶两个寄存器并写回左侧位置，或对栈顶值与数字 RK 常量运算。
   不复制读取，不交换操作数，不重排结合结构。SETTABLE 前必须只剩一个字段值。
2. **入口位置的捕获局部数组。** 同时保留只读捕获的原 SSA temp、可写捕获的原
   local 绑定；保留原声明／赋值形式。根定义自身必须被后续闭包引用捕获，不能用
   “同一物理寄存器的别的定义后来被捕获”替代证明。中间定义仍不得捕获、逃逸或参与 phi。
   数组完成后必须紧跟下一栈槽的 CLOSURE；调用前缀仍需证明栈布局。
3. **受限的开放尾项。** 仅用于捕获根数组：固定参数 CALL 的开放返回包由紧邻
   SETLIST 唯一消费，并保留为 HirPackTail::open。Lua 5.1 的 NEWTABLE 数组 hint
   不计这个未知长度表达式；批次编号和固定项个数仍精确匹配。
   后续只允许下一栈槽上的 CLOSURE / SETGLOBAL 配对与空 RETURN，不能读取或捕获
   开放结果的临时槽。开放参数、记录字段调用、嵌套开放数组和一般后续语句仍拒绝。

入口前缀额外接受被后续闭包捕获的 LOADK 局部常量。未被捕获的单次常量声明
仍不作为稳定栈槽依据，因为清理阶段可能删除它。

### newskill.lh：捕获身份之外还有两道门槛

抽查 SHA-256 `e696503589c600d0314096320166caeb92344624d87aab1dbc63cc7bf904f96f`：
首个残余数组位于主 proto LIR `@1941..@1972`，根为 r4，随后在 `@1975` 被闭包
与 r3/r2 一起捕获。此前已经执行大量全局初始化、循环与函数安装，不满足入口帧证明。

另一个独立问题是常量池索引超过 RK 的 255 上限：记录字段键不是动态计算，而是
通过 LOADK 加载 k662/k664/k666 等字符串，再由 `SETTABLE r5[r6] <- r7` 写入。
末条记录的一个值是运行时 GETGLOBAL，同样在“键寄存器＋值寄存器”布局下完成。
本轮记录恢复仅支持直接 RK 常量键，因此仅解决捕获身份还不能恢复此头文件。

下一步可先用小样本建立超过 255 常量的键／值寄存器布局证明，保持原 LOADK 与
GETTABLE/SETTABLE 顺序；再独立研究非入口位置的帧状态与作用域。两项都通过后才
适合重试整份头文件，不能预先把 11 份计入成功。

### skill.lh 与舞狮／疗伤：混合嵌套

抽查 skill.lh SHA-256 `b12b5dfec575bb25c3d8aa6e9662c50d116bb04429f9bf46ce07668c3703423a`：
首个残余数组是 tSchoolInfo；每条记录交错出现 GetEditorString 调用、运行时字段读取
和嵌套技能数组。需要记录字段调用与子数组的统一栈解析，并保持每次字段写入顺序。
舞狮、疗伤还有“记录表包数组”等相反方向，适合先用较小样本建立这项能力。

### 分支局部数组与开放返回值的余下情形

套马索、长歌、夜归人的残余构造位于分支中，部分还作为其他调用的参数；仍需要
旧寄存器内容、局部作用域和调用临时值生命周期证明。端午体型与无名剑二代虽然也有
开放尾项，但不满足本轮的入口／闭包安装后缀条件，不能直接套用疯子镖师的恢复。
